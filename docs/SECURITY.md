# 安全边界

一句话：聊天记录、agent 会话、房间状态都留在你自己的机器上，局域网里靠一张房间码认人。
这个插件**不做公网服务、不做账号体系、不加密传输** —— 它的威胁模型是「同一个 WiFi 下可信的人」，
不是「防得住同网段的人」。下面把每个面摊开写清楚，好用的人自己判断该在什么网络里开它。

## 谁能碰到什么

| 面 | 谁能进来 | 凭什么认人 | 明确不设防的部分 |
| --- | --- | --- | --- |
| 宿主本机接口 `/api/dsh.chatroom/*` | 已经登录这台 DSH 页面的浏览器 | 注册在宿主的 `connection.fetch` 上，准入由宿主做（本插件不自己验 Host / Origin，也不另开路由） | — |
| 局域网接口 `/lan/*` | 同一个网段里**知道房间码**的人 | 房间码换一个 `peerId`，之后每个请求都要带它 | 明文 HTTP、无速率限制、没有 TLS |
| 远程 agent 回合 | 只有拿着 `peerId` 的那台加入方 | 派发按 `peerId` 认领；回传必须是同一个 `peerId` + `assignmentId`，否则 403 | 回传文本原样当那位成员说的话入库，宿主不审内容 |

## 房间码就是凭据

- 六位，字母表是 `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`（去掉 `0/O/1/I`，念得出来、抄得下来），
  即 32⁶ ≈ 1.07×10⁹ 种；随机生成，同一份状态里不重复。
- 拿到码的人能进屋、能发言，在成员列里显示为那台机器上的人。**没有第二个凭据。**
- 没有登录失败的速率限制：想靠猜码进来，只能靠那 1.07×10⁹ 的空间和时间成本挡着。
  真要在意，就别把码贴在群里或截图里；换码就是解散重开一间屋。
- 宿主重启后 `peerId` 全部作废（它是每个进程现发的），对面要拿房间码重新握手。

## 明文传输与监听地址

- `node:http` 监听 `0.0.0.0:4399`（可用 `DSH_CHATROOM_PORT` 改）。第一次监听时系统防火墙会问，
  允许之后同网段就能连。
- **没有 TLS**：同网段里能抓包的人就能读到屋里的话。不要在没有 WPA 的开放网络里开。
- 消息不出这两台机器：插件自己不往任何第三方地址发东西；唯一的对外调用是你这台宿主的模型
  （走 DSH 自己的模型配置与凭据）。
- 加入方是只读镜像：规则、成员增删、解散都只能在宿主那台改。

## 接口面

| 路径 | 方法 | 凭据 | 说明 |
| --- | --- | --- | --- |
| `/lan/join` | POST | 房间码 | 换 `peerId`；空码 / 没有这间屋都是 403 |
| `/lan/ping` | GET | 无 | 只报机器名、是否在监听、代码版本与装载时间 |
| `/lan/state` | GET | `peerId` | 长轮询快照，只看得见自己加入的那间屋 |
| `/lan/message` | POST | `peerId` | 以自己那个人类成员的身份发言 |
| `/lan/messages` | POST | `peerId` | 往回翻历史；房间只从凭据里认，不看请求里说的 `roomId` |
| `/lan/assignments` | GET | `peerId` | 领自己那台机器的 agent 回合 |
| `/lan/reply` | POST | `peerId` | 回传某一轮；不是自己领的那条返回 403 |
| `/lan/self`、`/lan/agents`、`/lan/read`、`/lan/leave` | POST | `peerId` | 改名、补报名单、记已读、主动离开 |

共同约束：

- 未知路径 404，请求体必须是 JSON 且不超过 256 KB（超了 `too_large`），畸形请求行 400。
- `peer_unknown` / `room_not_found` / `code_required` 一律 403，其余错误 400；说不清原因的内部错误
  回 500 且不带堆栈。
- **不看请求头里的 `Host`**：它由请求方决定，`Host: [` 这类畸形值会让 `new URL` 抛
  `ERR_INVALID_URL`。base 写死，畸形包一个都带不走进程。
- **成功响应里不发 `Access-Control-Allow-Origin`**：局域网面的调用方是另一台机器上的插件进程
  （node 的 `fetch`，不看 CORS）和 `curl`；界面那半边调的是宿主 RPC，同源。放行头没有用处，
  只会多出一条「随便哪个网页都能读过本机聊天记录」的路。

## 哪些东西落在磁盘上

- `<profile>/dsh-chatroom/state.json`，**明文**：房间、消息、成员、链接、已读游标都在里面。
  它随 profile 备份与迁移一起走；同一台电脑上的其他用户能读到。
- 不落盘的东西：任何令牌、密钥、模型凭据（这些归 DSH 自己管），以及 `peerId`
  （只在内存里，进程结束即失效）。
- 原子写：先写 `state.json.tmp` 再 `rename`，断电最多留一个 tmp，不会写出半个 `state.json`；
  读坏了会另存成 `state.json.broken-<时间戳>` 再当空状态起来，不会静默吞掉旧文件。

## 明确不做

- 不做公网多租户、不做账号与邀请审批、不做端到端加密、不做附件与撤回。
- 不从消息正文推断权限：agent 回合照宿主的审批与权限走。
- 不代跑别的机器的 agent：本机 agent 只在本机自己的原生 session 里跑。
- 不对局域网流量做限速或封禁名单：能连上端口的人就是能试着进屋的人。
